# ADR 0001：EXIF 混合口径——像素面吃底座自动转正、查询面返 raw 尺寸

node 侧 image-renderer 的 EXIF orientation 处理定稿为**混合口径**：`drawImage` 的
像素面吃 @napi-rs/canvas 解码层的自动转正（canonical 空间），`imageIntrinsicSize`
查询面返回 raw（转正前）内在尺寸——orientation ≥5（90° 族）时把 canonical 宽高互
换回来。核心契约两侧不动：`drawImage(src, srcRect, dstRect)` 的 srcRect 恒为 raw
坐标（与查询面同系，ADR 0024），后端在原语内把 raw 源窗映射进 canonical 位图
（`canonicalSourceRect`，映射公式由「转正是逐像素双射、裁窗与转正可交换」反解，
与 go「先裁后转」逐像素等价，八向栅格测试与 go exif_test 的期望表互检钉死）。

## Considered Options

- **全 raw（对位 go：解码不转正、裁窗后由后端转正）**：需要后端逐像素自转正
  ——napi 位图到手已是 canonical，自行逆向还原要么放弃底座解码（换纯 JS 解码
  器，性能与格式覆盖全赔进去），要么二次变换引入插值损失。拒绝。
- **全 canonical（srcRect 也按 canonical 坐标）**：核心契约冻结（ADR 0022/0024
  五原语），srcRect 坐标系是三端（PHP GD / go / 浏览器）共享的 wire 契约面，改
  坐标系即改契约、连锁 PHP/go 两端与全部测试资产。拒绝。
- **混合口径（定稿）**：像素面与查询面各自就近吃底座的事实语义，差异在原语内
  一处消化（映射函数 + ≥5 互换），核心零改动、两端可见结果等价。

## 决议三条件（04 号决议原文锚定）

1. **三选一是真实取舍**：go 母版是「全 raw + 裁窗后转正」（decode.go：解码返
   内在坐标系全图；blitSource 裁窗 → exifOrientation ≠ 1 才 applyOrientation）；
   napi 没有转正开关——解码即 canonical。两侧语义不可兼得，混合口径是唯一同时
   保住「核心契约冻结」与「不放弃底座解码」的解。
2. **napi 自动转正无开关，出人意料**：解码层默认改写像素几何（90° 族连宽高都
   互换）且无法关闭，任何「以为拿到的是文件原样位图」的调用方都会被静默改写；
   实测还发现同步/异步口径分裂——`new Image(); img.src = bytes` 后同步读
   width/height 是 raw 头尺寸，可绘制 raster（经 loadImage/decode()）才是
   canonical。这条已写进 decode.ts/typography.ts 的实测钉死注释，版本精确钉
   1.0.13，任何升级必须过像素取样门禁。
3. **换库不可逆**：底座即渲染契约（文字栈、合成器、插值核全部绑定 skia 行为），
   换库（skia-canvas / node-canvas / 纯 JS）不是可逆切换而是全量重验。EXIF 口径
   的实现形态（映射缝在原语内、查询面 raw）随底座事实语义走，文档化于本 ADR 与
   04 号决议。

## Consequences

- **查询面 orientation 读取的实现偏离**：04 号决议原文写「用 exifr 读
  orientation」，落地改为与 go exif.go 同式复制的最小 JPEG APP1/TIFF 解析器
  （本包 `src/exif.ts`，约 90 行，注明出处）——exifr 全异步，而
  imageIntrinsicSize/drawImage 是同步契约口，异步库无法可用；同式解析器还与
  go 逐字节同语义、测试与 go exif_test 同手法互检。「≥5 互换返 raw」的决议
  语义不变，只是读取手段换成同步零依赖实现。
- **TTC 口径的有意收紧记录**：go image 侧字体入口接受 TTC（ParseCollection 取
  首个 face，静默）；node 两后端统一 fail-fast 拒收（魔数 `ttcf` 即抛，本包
  typography.ts）——响亮报错优于「多面 CJK 集合静默取默认面」，是对 go 的有意
  差异（05 号决议），不是镜像。
- **已知口径分裂记录在案**：浏览器 `naturalWidth` 是 canonical（canvas-web 仓
  域，既有事实）；本包查询面是 raw。若未来出现「90° 族 EXIF + 跨端严格逐像素
  一致」硬需求，走上游归一化另行立项，本 effort 不做（04 号决议原文）。
- **位图异步装配前提**：napi 位图 raster 须经异步解码才可 drawImage，而核心
  drawImage 是同步原语——后端增设 `preload(src)` 异步预备缝，默认 resolver
  物化时逐 src 预热（见 backend.ts 文件头「结构性差异」注）。这是实现形态约束
  而非语义改动：同步原语面、失败即抛纪律、静默不画缺省约定全部保持。
